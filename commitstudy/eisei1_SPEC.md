## 本文HTMLの書き方
見本: `/home/user/SalesforceCertification/commitstudy/afsvc/manuscript/out_ch1.json` の最初の2項目の html(構造と文体を合わせる。図(figure)は不要。図はあとで別に作る)。
各項目の `html` は、<article> と <h3> を除いた中身。次の順で並べる:
1. `<div class="co talk">…</div>` キャラの掛け合い(4〜6行)。
   - 話者: `<p class="tk pote"><b class="who">まなびん</b>…</p>`(学習者・くだけた口調)、`<p class="tk rou"><b class="who">クラウドちゃん</b>…</p>`(先生・です/ます)、`<p class="tk pen"><b class="who">コミットくん</b>…</p>`(ロボット・「〜だ」、短く、ときどきプログラミングのたとえ)。
   - 表情は任意で `data-f="smile|eager|sad|surprise|sweat|think|wink"` を p に付ける。
   - **項目ごとに掛け合いの型を変える**(出題して間違える/ボケとツッコミ/学習者が先に説明する/なぞなぞ/2人だけ/たとえ話のリレー/数字の語呂で覚える/専門用語をかみ砕く/職場で起きそうな場面から入る など)。毎回「質問→説明→補足→なるほど」にしない。同じ章で同じ型を2回続けない。
2. `<p class="one">` その項目を一言で説明する1〜2文。
3. `<div class="co tips"><p><b class="lab">たとえるなら</b>…</p></div>` 身近なたとえ。
4. 本体: `<h4>見出し</h4>` と `<ul>`/`<ol class="steps">`/表 `<div class="tw"><table><thead><tr><th>…</th></tr></thead><tr><td>…</td></tr></table></div>` を組み合わせる。知識は1つの <li> に1つ。
   - **数値は表にする**。しきい値・選任数・規模・頻度・保存年数・濃度・線量などは、本文の文章に埋めず、表の行にする(例: 衛生管理者の選任数、産業医の専属要件、健康診断の種類と時期、作業環境測定の頻度と記録の保存年数、事務所則の数値、年休の比例付与)。
   - 根拠の条文は、li や表のセルの末尾に「(安衛則7条)」のように短く添える。条文の引用(blockquote)は使わない。
5. `<div class="co trap"><p><b class="lab">取りこぼし注意</b></p><ul><li>…</li></ul></div>` 足切りを防ぐための、間違えやすい点を3〜5個(必須)。
   - 数字の取り違え(6月以内と1年以内、3年と5年、50人と100人)、「該当しないもの」の定番、似た制度の混同(労基則18条の業務と産業医専属の業務、技能講習と免許、ガスと蒸気 など)を書く。
   - 本文にある事実だけを、短く言い直す。
6. 必要なら2つ目の掛け合い `<div class="co talk t2">…</div>`(2〜3行、補足や語呂合わせ)。
7. `<div class="co memo"><p><b class="lab">試験ポイント</b></p><ul><li>…</li></ul></div>` 試験に出やすい点を3〜5個。
- 文体: です/ます。1文は短く。専門用語は初出で一言説明。Markdown記号は使わない。<b> は強調に少しだけ。法令用語は条文の表記に合わせる(「常時50人以上」「6月以内ごとに1回」など)。
- 1項目の本文はおよそ 1,000〜1,800 字(掛け合いを除く)。数値の多い項目は表が増えてよい。

### 取りこぼし注意まとめの項目(plan.json で `"plain": true`、問題数0)
各章の最後の項目。Data 360 の「試験で狙われやすいポイント一覧」(d360 の f-c7-points)と同じ形にする。
- html は、`<p>` 1〜2文(その科目の出題数・配点・足切りの問題数と、使い方)と、表 `<div class="tw"><table><thead><tr><th>分野</th><th>ポイント</th></tr></thead><tr><td>…</td><td>…</td></tr>…</table></div>` だけ。20〜30行。
- 掛け合い・one・tips・memo・trap は付けない。組み立てのときに `<article class="feat plain">` になり、「理解した」ボタンと練習問題のリンクは付かない。
- 行は、その章の各項目の本文にある事実だけ。分野の欄は項目の短い名前(例「衛生管理体制」「有機則」「作業環境測定」)。

## 問題の書き方
- 各項目につき plan.json の問題数。すべて**5肢択一**(選択肢5つ、正解1つ)。
  - アプリは5肢に対応している(選択肢は A〜J まで出せる。d360 にも5肢の問題がある)。選択肢の頭には番号を付けない(アプリが A〜E を付ける)。
- 実際の試験の形に合わせる:
  - 「〜に関する次の記述のうち、法令上、誤っているものはどれか。」「正しいものはどれか。」を中心に。
  - 「次のうち、法令上、○○に該当しないものはどれか。」(例: 作業環境測定士に実施させなくてよい測定、規格を具備しなければ譲渡できないものに該当しないもの、免許で選ぶ作業主任者)。
  - 組合せ問題: 記述をア〜オ(4〜5個)で並べ、「正しいものの組合せは次のうちどれか。」として、選択肢を「ア,イ」「ア,ウ」…のように作る。試験問題はA〜Eで記述を並べるが、アプリが選択肢に A〜E を付けるので、記述の記号は必ず**ア・イ・ウ・エ・オ**にする。
  - 穴埋めの組合せ: 「次の文中の[ ア ]〜[ ウ ]に入れる語句の組合せとして、正しいものはどれか。」選択肢は「ア:○○ イ:○○ ウ:○○」の形。
  - 計算問題(必要換気量、統計の率、年休の付与日数など)も入れてよい。
  - 事例型(「常時600人の労働者を使用する製造業の事業場で、うち深夜業を含む業務に常時40人…」)を各章に入れる。
  - 組合せ・穴埋めは各章の2割程度まで。
- 問題文の中で記述を並べるときは、改行(\n)で区切ってよい(アプリは問題文の改行を段落として出す)。
- 選択肢はもっともらしい誤りにする(数字を少しずらす、似た制度の値と入れ替える、主語を入れ替える、努力義務と義務を入れ替える)。
- 組合せ・穴埋め・数値が順に並ぶ問題は、選択肢の順番を固定したいので `"keep": true` を付ける(組み立てのとき並べ替えない)。ほかの問題は組み立てで並べ替える。
- `ex`(解説): 2〜4文。正解の理由と、誤りの選択肢がどこで違うか(正しい数値・正しい主体)を書く。「誤っているもの」を選ぶ問題では、正解の選択肢のどこが誤りで、正しくは何かを必ず書く。
- `u`: 根拠にした e-Gov の法令のページ(上の表の URL)か、MHLW などの公式ページの URL。
- `x`: **その問題の論点が書かれている本文の1要素の文字列そのもの**。同じ項目の html の中の <li> 1つ、<p> 1つ、または表の1行(<tr> の各セルの文字をつなげたもの)の、タグを除いた全文と完全一致させる。本文に論点がない問題は作らない(先に本文に書く)。取りこぼし注意(co trap)の <li> を x にしてもよい。
- `law`(任意): 改正に関わる問題は、「2025年6月施行の安衛則612条の2にもとづく」のように一言。施行前の改正を正解の根拠にした問題は作らない。
- 問題文・選択肢・解説はすべて日本語。法令の数字は算用数字(「50人」「6月以内」)。
